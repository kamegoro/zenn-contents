## TL;DR

- **tobira.nvim** は Vim の操作を**黙って観察**して、改善できそうなタイミングに「こっちのほうが良かったよ」とそっと教えてくれる Neovim プラグイン
- キーを封じない・割り込まない。操作はいつでも**自分のペース**でできる
- 148 コマンドの学習グラフを持ち、**自分のレベルに合った提案だけ**が届く
- `j` 5 回連打・`dw` → `i` → 書き直し・`f` の繰り返しなど、実際の癖をリアルタイムで検出する
- 一度覚えたコマンドでも、しばらく使わないと「忘れかけ」として再び提案に戻ってくる

## なぜ作ったのか

Vim を使い始めて数年経ちますが、こういう状態になっていました。

> 「今ある引き出しで何とかしている。新しいコマンドを積極的に覚えようとはしていない」

かといって、操作を強引に矯正されるほど熱量を注ぎたいわけでもない。ゆっくり自分のペースで気づけるものがほしくて、なかったので作りました。

というわけで作った tobira.nvim が、こちらです。

https://github.com/kamegoro/tobira.nvim

## tobira.nvim の動き

### 提案フロー

`vim.on_key()` でキー操作をパッシブに記録し続けています。1.5 秒間キー入力が止まると、直前の操作を解析してパターンを検出します。改善余地があれば画面右上にフロートウィンドウで提案が出ます。

![tobira の提案フロー — f を繰り返した直後に ; が提案される](/images/095599c1cd6a07/demo-suggest.gif)

自動提案はフォーカスを奪いません。作業を止めずに視界の端で見て、無視するもよし。表示時間は内容量に応じて 6〜9 秒で自動的に消えるので邪魔になりません。`:Tobira` で手動表示したときはフォーカス付きで開き、`q` / `<Esc>` で閉じられます。提案メッセージは日本語・英語を切り替え可能です（`lang = 'ja'`）。

通知ウィンドウのボーダー色は移動・編集・検索などカテゴリごとに変わり、本文には「なぜ今この提案が出たか」を説明する一行が必ず入ります（例: 「同じ行で f/t 検索を繰り返しました」）。理由を見せない通知は「なぜ出たか分からない」というストレスにつながるという調査結果を踏まえた設計です。提案したコマンドを実際に使うと、初回だけ小さな祝福トーストが出ます。

### 検出しているパターン（34 種類）

**移動系**

| やってしまいがちな操作 | tobira の提案 |
|---|---|
| `fa` → `fa` と同じ行で繰り返す | `;` — 直前の f/t/F/T を繰り返す |
| `j` を 5 回以上連続 | `{n}j` — カウントプレフィックス |
| `j` を 10 回以上連続 | `}` — 段落単位で移動 |
| `l` を 5 回以上連続 | `w` — 単語単位で移動 |
| `0` → `w` で行頭移動 | `^` — 最初の非空白文字へ |
| `0` / `^` → `i` | `I` — 行頭から挿入 |
| `$` → `a` | `A` — 行末に追記 |
| `k`（1 回）→ `o` | `O` — 上に新しい行を開く |
| 検索後に `n` を 4 回以上 | `cgn` — 次のマッチを変更 |

**編集系**

| やってしまいがちな操作 | tobira の提案 |
|---|---|
| `dw` → `i` → 書き直す | `cw` — 削除 + 挿入を 1 コマンドで |
| `c$` | `C` — 行末まで変更（短縮形） |
| `d$` | `D` — 行末まで削除（短縮形） |
| `yy` → `p` | `yyp` — 行の複製 |
| `dd` → `p` | `ddp` — 行を下と入れ替え |
| `dd` → `i` / `a` / `o` | `cc` — 行全体を変更 |
| `dd` を 3 回以上 | `{n}dd` — N 行まとめて削除 |
| `x` → `i` / `a` / `o` | `s` — 1 文字削除 + 挿入 |
| `x` を 3 回以上 | `{n}x` — N 文字まとめて削除 |
| `u` を 3 回以上 | `<C-r>` — redo でやり直す |
| `r{x}` を 3 回以上 | `R` — Replace モードで連続置換 |
| `>>` を 3 回以上 | `{n}>>` — N 行まとめてインデント |
| `v` `i` `{obj}` `c/d/y` | `ciw` / `di"` など — 直接 text-object を使う |

この他にも `k × 10 → {`・`p × 3 → {n}p`・`.× 3 → {n}.`・`J × 3 → {n}J` など 34 種類を検出します。完全な一覧は `:help tobira-patterns` で確認できます。

### 採用を「行動」で検出する

提案した後、tobira はそのコマンドを実際に使ったかどうかをパッシブに監視しています。ボタンを押す必要はなく、提案されたコマンドを使えば自動的に「採用」とみなします。

採用されたコマンドは累計 100 回使用を超えると「習得」扱いになり、以降は提案されません。ただし習得は一方通行ではありません。しばらく使わずに最近の使用頻度が過去の平均より大きく落ち込むと「忘れかけ」と判定され、`:TobiraGuide` に `⟳` マーク付きで再び現れます。「知ってる」を聞かず行動だけで判定する、という方針を忘れる方向にも一貫させています。

### ガイドパネル

`:TobiraGuide` でレベルに応じたチートシートを開けます。習得済みのコマンドは自動で隠れるので、**次に狙うべきコマンドだけ**が並びます。各コマンドの右には使用回数が出るので、「もうこれは分かってるやつだ」と一目で認識できます。

![TobiraGuide — チートシートパネル](/images/095599c1cd6a07/demo-guide.gif)

### スキルツリー

`:TobiraProgress` で現在のレベルと学習グラフを確認できます。ヘッダーには全体の習得率（`132 / 480 mastered` のような形）、各カテゴリの見出しにも `done / total` が出るので、迷子にならず「今どのくらい進んでいるか」が一目で分かります。

![TobiraProgress — スキルツリーとレベル表示](/images/095599c1cd6a07/demo-progress.gif)

グリッド自体は静かなままにして、カーソルを乗せたコマンドの詳細（使用回数の推移を示すスパークライン・状態・次の★までの距離）は下のプレビュー欄にだけ出す作りにしています。一覧性と情報量を両立させたかったので、常時全部出すのではなく「見たいときだけ見える」設計にしました。

各コマンドの左にはマステリーグリフが表示されます。

| 表示 | 意味 |
|---|---|
| （なし） | 未使用 |
| `☆` | 1 回以上使用 |
| `★` | 100 回以上 |
| `★★` | 1000 回以上 |
| `★★★` | 5000 回以上 |
| `⟳` | 忘れかけ（過去はよく使っていたが、最近の使用頻度が大きく落ちた） |
| `✗` | サプレス済み（提案しない） |
| `●` | ピン留め（`:TobiraGuide` と `:TobiraProgress` の両方で常時表示） |

カーソルを合わせた状態で `x` を押すとサプレス／解除、`p` でピン留め／解除。`g` で `:TobiraGuide` へ、`s` で `:TobiraStats` へジャンプできます。`q` / `<Esc>` で閉じます。

レベルは `novice / beginner / intermediate / advanced` の 4 段階で、**自分の操作ログから自動判定**されます。レベルに応じて提案されるコマンドが絞られるので、beginner のうちに `cgn` の提案は届きません。

### 使用状況のスナップショット

`:TobiraStats` を開くと、一番上に**効率ギャップ**（使い倒しているのに隣のコマンドを試していない上位 5 件）が来ます。マステリーバーやよく使うトップ 8 はその下、総打鍵数と発見済みコマンド数は一番下に控えめに表示されます。「見て楽しい数字」より「見て次の行動が決まる情報」を優先したかったので、あえてこの順番にしています。

![TobiraStats — 使用分布と効率ギャップ](/images/095599c1cd6a07/demo-stats.gif)

「そろそろ隣の扉を開けても良さそう」なコマンドがまず目に入るので、`:TobiraGuide` と組み合わせて次の学習ターゲットをすぐ決められます。

## インストール

**lazy.nvim**

```lua
{
  "kamegoro/tobira.nvim",
  event = "VeryLazy",
  opts = {},
}
```

設定オプションはすべて省略可能で、`opts = {}` だけでも動きます。

```lua
require("tobira").setup({
  lang                = 'ja',    -- 'en' | 'ja'
  idle_delay          = 1500,    -- 提案を出すまでの待機時間（ms）
  idle_suggestions    = true,    -- idle トリガーの提案を有効にするか
  suggestion_cooldown = 300,     -- 自動提案の最小インターバル（秒）
  max_shown           = 2,       -- 同じコマンドを提案する最大回数/セッション
})
```

**コマンド一覧**

| コマンド | 説明 |
|---|---|
| `:Tobira` | 今すぐ次の提案を表示（クールダウン無視）。`q` / `<Esc>` で閉じる |
| `:TobiraGuide` | チートシートパネルを開閉 |
| `:TobiraProgress` | スキルツリーとレベル、カーソル連動の詳細プレビューを表示。`x` でサプレス、`p` でピン留め |
| `:TobiraStats` | 使用分布・マステリー・効率ギャップを表示 |
| `:TobiraReset` | 学習データをリセット |

`:help tobira` で全オプション・コマンドのドキュメントを参照できます。

## tobira.nvim の立ち位置

既存の Vim 学習補助プラグインと比べたときの位置づけです。

| プラグイン | 動き | tobira との違い |
|---|---|---|
| [hardtime.nvim](https://github.com/m4xshen/hardtime.nvim) | 非効率な操作をブロックして矯正 | tobira は**ブロックせず**、後から一言だけ教える |
| [precognition.nvim](https://github.com/tris203/precognition.nvim) | 使える motion を常時オーバーレイ表示 | tobira は**あなたが得しそうな瞬間**にだけ出る |
| [spamguard.nvim](https://github.com/timseriakov/spamguard.nvim) | キー連打を検出して警告 | tobira は連打だけでなく**コマンドグラフ全体**を扱い、習熟度も追う |
| [pathfinder.vim](https://github.com/AlphaMycelium/pathfinder.vim) | 効率的なカーソル移動を提案 | tobira は移動だけでなく**編集・検索・text-object**まで対応 |
| [vim-be-good](https://github.com/ThePrimeagen/vim-be-good) | ゲーム形式の練習 | tobira は**自分の実操作**にパーソナライズ |

hardtime.nvim と tobira.nvim は競合しません。「hardtime が悪い癖をブロックし、tobira が次の扉を開ける」という使い方ができます。

## 技術的なポイント

### vim.on_key() だけで全操作を把握する

tobira は `vim.on_key()` 以外のキー追跡 API を一切使いません。`TextYankPost` などの autocmd を使うと操作の一部しかカバーできず、ユーザーのキーマッピングを書き換えるリスクもあります。`vim.on_key()` は全キーストロークを受け取るため、演算子文法を自前でパースすれば意味レベルの検出が可能です。

Neovim 0.10 から `vim.on_key()` のコールバックに `typed`（ユーザーが実際に打鍵した物理キー）引数が追加されました。`D` を押すと Neovim 内部で `d` と `$` が展開されますが、`typed` を見ることで「ユーザーが打ったのは `D` 1 キー」と正確に判断できます。0.9 以前でもフォールバックで動作します。

### 状態機械でパターンを検出

`d3w`・`diw`・`daw` はどれも「削除 + motion」なので同じパターンとして扱いたい。また `gj`・`zz` などの 2 文字コマンドは `j` や `z` 単体と区別したい。これらを `vim.on_key()` 1 発 1 発から意味として拾うために、`patterns.lua` に小さな状態機械を実装しています。

```
d / c が来る → pending_op = 'd' | 'c'

pending_op 中:
  [1-9]             → カウント数字（d3w 対応）
  dd / dj / dk      → 行削除
  i / a の後        → text-object 待ち（diw / daw 対応）
  w / e / $ など    → charwise（dw として扱う）
  <Esc>             → キャンセル
```
